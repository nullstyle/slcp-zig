# Stability

What a consumer of `slcp-zig` may rely on across releases, how that promise is
enforced, and how a symbol gets promoted. This file is the review reference
`zig build check-api` points at when it goes red.

**Status: INTERIM (M6 stage S1c).** The Stable list below is today's surface
only. The M6 API freeze (stage S6) promotes the M6 additions (`slcp.Quorum`,
`slcp.nodeId`, `slcp.AppNode`, `slcp.Codec`, `slcp.lint_report`, the CLI's
`--help` contract) and finalizes this document before v0.1.0 is tagged.

## The two tiers, and how they are enforced

Every `pub` declaration reachable from the `slcp` module is in exactly one of
two tiers. The categorizer is `stable_rules` in `tools/api_snapshot.zig`; it
**defaults every path to Experimental**, so a brand-new symbol can never be
frozen by accident — only by a deliberate rule.

| Tier | File | Gate |
|---|---|---|
| **Stable** — the frozen contract | `docs/api-snapshot.txt` | `zig build check-api` is RED on any drift, on every OS. |
| **Experimental** — may change at any 0.x bump | `docs/api-snapshot-experimental.txt` | Refreshed in place by local `check-api`; CI's ubuntu job runs `-Dstrict-experimental=true`, which is RED when the committed file is stale. |

A third, implicit tier is **Internal**: anything not `pub`, plus test-only
code. It never appears in either file.

Two further gates keep the frozen file honest:

- `zig build api-closure` fails when a Stable function's signature mentions an
  Experimental type. A frozen entry point that takes an unfrozen type is only
  nominally frozen — the type can change shape under it while `check-api`
  stays green — and if no Stable API can construct the type, the entry point
  is unusable on its own terms.
- A comptime **rule-liveness assertion**: a `stable_rules` entry that matches
  no declaration is a compile error. A rule for a renamed symbol cannot
  silently document a contract nobody can rely on.

Snapshot lines pin more than names: struct **fields and their default
values**, union variants, enumerant values, and **fully expanded error sets**
(an inferred `!T` is rendered as a sorted `error{...}` list, so adding or
renaming an error a consumer might `switch` on is visible).

Until S6, `check-api` and `api-closure` are separate steps that CI does not
run; only the tool's unit tests (`api-snapshot-tests`) are inside
`zig build test`. S6 folds both gates into `test` and CI.

## What is Stable today

Grouped by area. "prefix" means the type and all of its members/fields are
frozen; "exact" means the one symbol only (its fields stay Experimental).

**The omakase node (`slcp.node`, re-exported as `slcp.Node` / `slcp.NodeOptions`)**
- `Node` (exact — its fields are internal state) with `create`, `deinit`,
  `propose`, `waitExternalized`, `stats`, `boundPort`, `allocator`.
- `Node.WaitOptions`, `Options`, `Externalized` (prefix): the option/value
  structs a consumer builds or reads, including every default
  (`strict_canonical = true`, `max_value_bytes = 4096`, `start_slot = 1`, …).

**Keys (`slcp.keys`)**
- `KeyPair` (prefix), `loadOrCreate`, `ephemeral`, `Error`.

**Driver vtable (`slcp.core.driver`, design §8.2)**
- `Driver` (prefix: the vtable field shapes and `default()`), `Validity`
  (prefix), `DriverError`. A future `driver.Checked` is Experimental (R16).

**Sans-io engine (`slcp.core.engine`, design §5) — the power-user escape hatch**
- `Engine` (exact) with `init`, `deinit`, `pushInput`, `popEffect`,
  `commitEffect`, `stats`.
- `Input`, `Effect`, `Config`, `InputStatus`, `PhaseKind`, `TimerId`, `Stats`
  (prefix): the input/effect vocabulary, variant by variant.
- `EngineError`, `PushError`, `timeoutMs`.
- `slcp.core.limits` (whole module): the frozen wire limits and `Limits`.

**Quorum set value type (`slcp.core.qset`)**
- `QuorumSetOwned` (prefix: the three fields a consumer constructs),
  `validateAndNormalize`, `hashNormalized`, `canonicalBytes`, `Error`,
  `NodeId`, `max_depth`, `max_total_validators`. The lint surface (`lint`,
  `LintFinding`, `LintCode`, …) is Experimental until S6 (R13 adds a fourth
  code).

**The wasm host ABI (`slcp-abi.*`, design §7)**
- Every `export fn`, every `extern "slcp_driver"` import, and `abi_version`.
  These lines are rendered from the TEXT of `src/wasm/slcp_host_abi.zig`
  (the module pins `std.heap.wasm_allocator` and cannot be imported
  natively), and the runtime half of the liveness assertion checks the
  `slcp-abi` rule against the parsed file.

## What is Experimental today (and why)

- `slcp.overlay`, `slcp.timers`, `slcp.store`, `slcp.wire`: the node's
  internals, public only as escape hatches. Their shapes follow the
  implementation.
- `slcp.core.qset.lint*`, `fromReader`, `exciseNode`, `clone`: lint gains a
  code in M6; the reader-taking functions expose generated types.
- `slcp.core.gen.*` (generated by capnpc-zig from `schema/*.capnp`): the
  **wire format** is frozen by the schema and the conformance vectors, not
  by the Zig accessor names.
- `slcp.core.{canonical, crypto, statement, stored, values, local_node, slot,
  nomination, ballot, pending, qset_store, emit, host_codec}`: engine
  internals reachable through the `core` escape hatch.
- `slcp.core.capnpc`: capnp-zig's own module, re-exported. Frozen by
  **upstream's** snapshot gate; not walked here.

## Platform support

| Leg | Gate |
|---|---|
| Linux x86_64 (ubuntu-latest) | `test`, `wasm`, `wasm-diff`, `e2e`, `fmt-check`; from S6 also `check-api -Dstrict-experimental=true`, `api-closure`, `gen-check`. |
| macOS arm64 (macos-latest) | `test`, `wasm`, `wasm-diff`; from S6 `check-api` (Stable file strict; the experimental file is strict on macOS only after one green run — R20, because `@typeName` can spell std types per-OS). |
| wasm32-freestanding | the ABI artifact (`zig build wasm`) + its differential replay. |

Platform-dependent spellings of the same std type are canonicalized by
`platform_type_aliases` in the tool (today: the `sockaddr` family), so the
Stable file is byte-identical across the matrix.

## Promoting a symbol

1. Add a rule to `stable_rules` — `p("path")` to freeze a subtree,
   `e("path")` for one symbol — with a comment saying *why* the shape is a
   contract (a struct consumers construct → prefix; a type with internal
   fields → exact + its methods).
2. `zig build api-closure`: if the new entry point mentions an Experimental
   type, decide — promote the type, or narrow the entry point.
3. `zig build api-snapshot`, review the diff of `docs/api-snapshot.txt` line
   by line, commit both files with the rule.

Demoting or changing a Stable line is a breaking change: it needs a
CHANGELOG entry and, pre-1.0, a minor version bump.

## Semver, pre-1.0

`0.x.y`: `y` bumps never change a Stable line; `x` bumps may, each change
listed in the CHANGELOG with the `check-api` diff as its evidence. The
Experimental file carries no promise at all.
